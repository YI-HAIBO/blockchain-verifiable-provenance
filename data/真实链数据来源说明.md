# 真实链数据来源与审计说明（M1 闭环）

本文件说明论文 §4「Real-chain evaluation」所用真实链上数据集的来源、字段、
获取方式与复现命令。**所有数据均来自以太坊主网链上记录，无合成或生成值。**

---

## 一、来源

| 项 | 值 |
|---|---|
| 链 | Ethereum Mainnet（chain id 1） |
| 数据类型 | ERC-20 `Transfer(address,address,uint256)` 事件日志 |
| 事件 topic0 | `0xddf252ad1be2c89b69c2b068fc378daa952ba7f163c4a11628f55a4df523b3ef` |

采集方式：对 `eth_getLogs` 按 5 区块窗口分批请求并过滤「topic 数 = 3」的

`transactionHash`、`logIndex`、合约地址、`topics[1]`／`topics[2]` 的收发地址
与 `data` 中的转账数量；区块时间戳另经 `eth_getBlockByNumber` 并发获取。
采集脚本见 `C:\Users\Yi\WorkBuddy\2026-11-11-18-04-28\fetch_real_chain.py`。

## 二、导出文件

| 文件 | 用途 |
|---|---|
| `real_erc20_flat.csv` | Schema A 扁平导出（`key,value`），供 `--source real` 直接读取 |
| `real_erc20_audit.csv` | 逐行溯源：`block_number, tx_hash, log_index, contract, from, to, value, ts` |
| `real_chain_meta.json` | 端点、区块范围、记录数、合约数、导出时间的机器可读元数据 |

字段语义：

- `key` ＝ `erc20:<12 位区块号>:<交易哈希>:<6 位日志序号>`，保证字典序可排序且唯一。
- `value` ＝ `<token 合约>,<from>,<to>,<token 最小单位转账数量>`，四段均为链上原值。
- `run_full_eval.py` 的计数聚合器取 value 首段分组，因此真实链实验度量的是
  **按 token 合约分组的转账笔数**；论文已如实说明该分组语义，未把它表述为
  supply-chain 阶段或投票候选人。

## 三、复现命令

```bash
cd blockchain_bench
python run_full_eval.py --source real \
  --data-path data/real_erc20_flat.csv \
  --n 5000 --workload supplychain
```

结果写入 `results/full_eval.json`（`_meta.source = real`）。此前的合成实验
结果保留为 `results/full_eval.synthetic.bak.json`。

## 五、诚实边界

1. 真实导出覆盖 10 个连续区块、6,000 条事件，`scaling` 因此只到 n = 1,000；
   论文未把该数据集表述为大规模真实数据集。
2. 版本化（time-travel）、可变状态、删除与分叉实验需要 Schema B／C／D 导出
   （`version,key,value`、`op,key,value,version`、`...branch`），本次只提供了
   Schema A。这些实验在真实链运行下优雅降级为明确错误，并在论文中仍以
   合成 trace 报告，正文 Scope 与真实链段落均已明确标注。
3. 所有数值来自本机实跑，未对任何基线做估计或补值；vChain／GEM²-tree／
   MBFT 等同平台对照未复现，槽位保持为空。
